本地 `product_archive_size_chart_mapping` 当前为空；也就是说目前生效的是代码固化规则，还没有额外的 AI/人工审核覆盖规则。

### 1.4 重要缺口

当前规则是按字段文本精确归一后匹配，暂未把 `衣长(cm)`、`胸围(cm)`、`肩宽(cm)`、`体重(kg)` 这类带单位后缀的平台字段归一成 `衣长`、`胸围`、`肩宽`。因此好衣库、抖音等带单位模板当前会出现大量未命中，需要下一步补单位归一或走 AI 推荐。

## 3. 建议

1. `208326104204` 优先改看 `66 裤套装` 或 `9783 中性童装 / 套装`，而不是当前 `12412 blbl&mini / 套装`。
2. 把 `前浪`/`后浪` 作为 `前裆`/`后裆` 的中置信字段需要人工确认；如果业务确认稳定，可提升为高置信。
3. 增加字段名单位归一规则：`衣长(cm)` -> `衣长`、`胸围(cm)` -> `胸围`、`肩宽(cm)` -> `肩宽`、`裤长(cm)` -> `裤长` 等，否则抖音/好衣库模板会漏填。
4. `领口`、`领围`、`身高`、`体重`、`年龄`、`安全等级`、`克重` 不应强行从 PLM 测量点映射；应走 MDM/SKU/固定规则/人工配置。
