# 深绘服饰 / 鞋品建档字段实现规范

## 文档定位

本文是 Listingify 当前代码的可执行字段规范，供运营核对、研发维护和回归验收共同使用。历史群聊证据、逐款反馈和探针记录见 [`deepdraw-field-mapping-rules.md`](./deepdraw-field-mapping-rules.md)。两份文档冲突时，以本文件的“当前实现”及当前深绘类目模板为准；群聊截图和附件只作为证据，不构成线上发布授权。

适用范围：

- 服饰和鞋品的深绘商品档案草稿。
- MDM、标准文案表、上市计划、PLM 尺码表、吊牌/洗唛/鞋盒 OCR、商品参考图到深绘字段的映射。
- 草稿字段重建、AI 补值、校验、创建 payload、创建后完整更新和回读。

当前字段实现由以下变更脉络组成：

- `19cf34c`：对齐 8 月 28 日鞋品和服饰二次反馈。
- `4e7cb2c`：曾恢复多平台尺码发送，并完成报告字段、鞋品禁填、枚举优先级、标题边界和鞋盒 OCR 规则；后续真实接口验证证明旧写法会触发 `10499`，当前正常发布默认不发送多平台尺码，探针脚本保留最小多平台 payload 继续定位真实 API 形态。
- 本次补丁：鞋品和服饰销售尺码按类目保留单位；主表、唯品会、天猫、抖音等稳定结构表继续进入正常发布；多平台尺码草稿侧继续生成，但只在探针脚本显式放行时发送。

## 一、完整处理链路

1. 根据款号读取 MDM SPU/SKU，并关联当前草稿选定的深绘租户、商户和类目。
2. 读取当前深绘类目模板，并采用模板当前的字段 ID、类型、必填性、父子关系和枚举。草稿可保留 mapping 中的诊断字段，但只有当前模板中存在并取得字段 ID 的字段才允许发送。
3. 读取适用于当前产品线的字段 mapping。`通用`规则始终适用；鞋品、中童等产品线规则只在 MDM 类目命中时生效；非模板历史 mapping 不得成为发布阻断项。
4. 合并标准文案表、上市计划、PLM 尺码表、鞋品尺码基准、人工值和已导入图片。
5. 先执行禁填和确定性规则，再生成 MDM/SKU 字段、尺码表和商家 SKU。
6. 对枚举值执行当前模板归一化；未命中当前枚举的值不得直接发送。
7. AI 填充时先执行证据规则和材质规则，只把剩余的空值、无效值或需视觉复核的枚举交给模型；单选、多选和其他带选项字段最终保存当前模板的可见枚举文案，`attrValueId`、`id`、`code` 等只作匹配辅助，不作为推荐值或落库值。
8. 重建后运行必填、父子字段、枚举、销售尺码、尺码表行键、SKU 组合等校验。
9. 鞋品创建时只发送安全创建字段和主尺码表；取得数值 `productId` 后，用完整更新补写主表、唯品会、天猫、抖音。多平台尺码草稿侧继续生成，但不进入正常发布；线上探针必须以业务码 `10200` 和资源回读一致为准。
10. 回读必须逐项核对销售尺码、颜色/尺码 SKU 组合和结构表，不能只看 HTTP 200。

## 二、来源优先级与冲突处理

| 优先级 | 来源 | 使用边界 |
| --- | --- | --- |
| 1 | 人工确认、吊牌/洗唛/鞋盒 OCR | 合规、执行标准、安全等级、真实成分、充绒克数等原始证据优先；鞋盒执行标准可覆盖文案表或上市计划值 |
| 2 | MDM SPU/SKU | 款号、品牌、吊牌价、颜色、销售尺码、SKU、条码、性别/季节等主数据 |
| 3 | 标准文案表 | 标题、推荐理由、导购标题、FAB、材质、细节文案、版型、厚薄、弹性等 |
| 4 | 上市计划 | 类目、主款式、产品季、属性、日期、执行标准、尺码段等 |
| 5 | PLM / 统一尺码基准 | 服饰量体、年龄、体重、抖音重量、推荐号型；鞋品脚长、内长和平台备注 |
| 6 | 确定性规则 | 价格差、固定枚举、平台标题组合、产地、物流、字段互备、枚举归一 |
| 7 | AI | 只处理仍缺失且允许判断的模板枚举；不能覆盖更高优先级事实 |

补充规则：

- 人工已修改字段在草稿重建时保留，但已被明确废弃的 AI 尺码表、错误材质 fallback、错误年龄值和鞋品禁填项会被清理。
- 父字段条件未激活时，子字段统一改为 `skip`，不必填、不阻断、不发送。
- 同一条反馈有两张截图时，内容多的图作为期望字段和值，内容少的图作为本次草稿缺失项；明确文字修正高于截图推断。
- 不在以下表格中单列的模板字段，仍按导入的 `deepdraw_field_mapping_rule` 执行；没有 mapping、固定规则、可靠证据或允许的 AI 策略时保持为空。

字段 mapping 的 `source_type` 执行语义：

| source_type | 取值方式 |
| --- | --- |
| `fixed` | 使用规则默认值；若默认值是吊牌价、款号、文案字段等引用表达式，则先走对应确定性派生 |
| `mdm` | 从 MDM SPU 字段读取；颜色、尺码和商家 SKU 由专门的 SKU 派生逻辑生成 |
| `launch_plan` | 确定性字段派生优先，其次上市计划指定列，最后规则默认值 |
| `copywriting` | 确定性字段派生优先，其次标准文案表指定列，最后规则默认值 |
| `manual` | 保留人工默认值或可解释的引用派生；没有值时等待人工/允许的 AI |
| `skip` | 留空且不发送；只有 AI 策略明确设置 `includeWhenSourceSkipped` 的枚举才可进入保守复核候选 |

所有 source type 最终都要经过当前模板枚举归一、父子字段判断和必填校验；mapping 不能绕过模板。
旧 mapping 标为 `skip` 的 `产品类别/商品类别` 和鞋品 `鞋垫材质`，在 AI 填充阶段属于明确例外：前者可用深绘类目路径、上市计划和 MDM 类目归一；后者有明确鞋垫证据时归一，无证据且模板存在`其他/其它`时仅兜底该枚举。

### 3.5 服饰尺码表

主尺码表、唯品会尺码表、抖音尺码表是服饰业务必填结构字段。多平台尺码按图 1 规则在草稿侧生成，但在开放 API 写入形态稳定前不进入正常发布 payload；线上探针必须以业务码 `10200` 和资源回读为准。

| 场景 | mapping 规则 |
| --- | --- |
| 主表尺码列 | 主尺码表行键保留 `XXcm/XX码` 展示值；表内第一列固定新建 `尺码`，单元格填写去掉 `cm/码` 的裸数字 |
| 上装主表 | `尺码` 后续列为衣长→衣长，肩宽→肩宽，胸围→胸围/1/2胸围，袖长→袖长/袖长肩点量/内袖长 |
| 裤装主表 | `尺码` 后续列为裤长→裤长，臀围→臀围/1/2臀围，腰围→全腰围/腰围/1/2腰围，脚口→1/2脚口 |
| 裙装主表 | `尺码` 后续列为裙长、腰围、臀围、下摆围，分别匹配 PLM 同义量点 |
| 中置信量点 | 前后浪/前后裆、大腿围、袖笼围按固化同义量点推荐，保留人工审核语义；袖口可以存在于 PLM 源数据，但服饰发布尺码表不构建袖口/袖口围列 |
| 围度换算 | 目标为胸围、腰围、臀围、脚口、裤口围且来源量点含`1/2`时乘 2；其他量点不套用 |
| 空列处理 | 某列任一尺码为空或为 0 时整列移除；不能用 0 伪造完整表 |
| 尺码裁剪 | 只保留当前 MDM SKU 存在的销售尺码 |
| Balabala 年龄/体重 | `尺码数据模板.xlsx / balabala` 提供每个尺码的年龄、kg、抖音斤数 |
| 推荐号型 | 先判男/女/中性，再判上装/下装；任一维度无证据就不填 |
| 京东尺码 | 京东规格/自营尺码子属性从当前真实 SKU 尺码生成并去掉 `cm`，不得使用颜色或空 SKU；平台单元格去掉 `cm`，主表行键和销售尺码保持原标准值，主表内 `尺码` 列单独填裸数字 |

## 五、识图与 OCR 逻辑

### 5.1 图片入口和分类

- “导入吊牌/洗唛/平铺图”统一接收 JPG、PNG、PDF；商品参考图还支持本地 WebP。
- 文件名含吊牌、合格证、`hangtag/tag`归为吊牌；含洗唛、洗标、水洗、`wash`归为洗唛。
- 文件名含鞋盒或 `shoe-box/shoebox`归为吊牌类 OCR，因此鞋盒执行标准进入最高优先级链路。
- 普通商品图、平铺图和抓虾图包进入参考图；不会把附件里的操作文字当作用户指令。

### 5.2 OCR 可识别字段

| OCR key | 目标字段 |
| --- | --- |
| productName | 产品名称、商品名称、品名 |
| articleNo | 产品货号、商品货号、货号、款号 |
| executionStandard | 执行标准、执行规范 |
| safetyCategory | 安全等级、安全技术类别/要求 |
| productGrade | 产品等级、质量等级 |
| materialComposition | 材质成分、面料成分、成分含量文本及有枚举的材质/面料字段 |
| downFillWeight | 无枚举的充绒量文本字段 |
| washCare | 洗涤说明、洗护说明、洗涤方法 |
| rawText | 吊牌截取或洗唛截取字段 |

OCR 冲突规则：

- 同字段先比识别置信度，再按吊牌 > SCM 清单 > 洗唛 > unknown 排序。
- 默认不覆盖已有值；显式选择覆盖时才覆盖。
- 例外：吊牌类文档中的执行标准始终可覆盖已有文案/上市计划值，鞋盒因此具备最高优先级。
- 同款不同色存在多份充绒量时，逐尺码取较小克数，并记录合并证据。
- OCR 值仍需通过当前模板枚举校验；不兼容值只预览，不写入。

### 5.3 商品参考图判断

参考图用于可见事实，不用于猜合规或结构化数据：

- 服饰：款式、图案、色块/拼接、袖长、衣长、领型、门襟、腰型、版型、帽子、腰带、毛领、套件数量、穿着方式、内胆类型等。
- 鞋品：图案、鞋型、鞋帮高度、25鞋子模板类型及凉鞋结构；标题、类目和 SKU 尺码段只作辅助。
- 服饰主体与袖片、帽片、口袋有清晰不同材质或色块时，优先`拼色/色块`，不能因主色占比高选择`纯色`。
- 鞋品有明显条带结构时选`条纹`；无印花/图形且整体无图案时可选`纯色`。
- 凉鞋：鞋头和后跟都露空→前后空凉鞋；前后均包覆且中部镂空→中空/镂空凉鞋；看不清则不填。
- `模特实拍`优先由抓虾图包元数据和文件名是否有模拍确定，不必交给模型猜。
- 图片不能单独证明材质成分、百分比、安全等级、执行标准、充绒克数、商家 SKU 或尺码表。

## 六、AI 字段逻辑

### 6.1 候选生成顺序

1. 只考虑当前模板有枚举的字段。
2. 字段为空、枚举无效、SKU 颜色未命中模板，或鞋品特殊枚举需要复核时，才进入候选。
3. 先执行置信度 0.96 的确定性证据规则：绒子含量互备、填充物证据、颜色归一、单位、型号、模特实拍、版型、厚薄、弹力等。
4. 再执行材质成分规则，把已识别成分归一为模板材质枚举。
5. 剩余候选才发送给多模态 AI。

### 6.2 AI 优先级

| 优先级 | 字段组 | 主要证据 | 硬边界 |
| --- | --- | --- | --- |
| P0 | 款式、类型、分类、产品类别、图案、流行元素、袖长、衣长、领型、门襟、裤长、腰型、版型、帽子/腰带/毛领/套件、穿着方式、内胆、鞋品模板/凉鞋结构、靴筒高度 | 参考图优先，标题、类目、来源表和已填字段辅助；产品类别优先使用深绘类目路径、上市计划和 MDM 类目 | 图片不清或无法交叉验证就省略；非鞋品禁止填鞋品枚举；产品类别必须命中当前模板枚举 |
| P1 | 年龄、人群、季节、性别、风格 | MDM、尺码段、标题、来源表，图片只辅助季节/风格 | 年龄不能凭图片猜；无尺码段或明确标题证据就省略 |
| P1 | 面料、材质、成分、填充、厚薄、弹力、柔软、功能、工艺 | 文案、吊牌、洗唛、已填成分，图片只辅助观感 | 无成分证据时不得凭图片猜材质或百分比 |
| P2 | 详情页AI标注、模特实拍 | 图包结构、参考图和上下文 | 优先级低；证据不足留空；服饰主图4样式已固定为 225，不交给 AI |

### 6.3 模型输入与落库门槛

- 最多发送前 4 张本地参考图，每张不超过 4 MB，仅接受 JPEG/PNG/WebP 数据 URL。
- 同时发送 MDM 摘要、SKU 颜色/尺码、来源表摘要、已填可信字段、当前类目路径和候选字段；非颜色候选最多携带当前模板前 120 个枚举，颜色候选保留全部当前枚举。
- 模型只能返回候选字段 ID 和该字段现有枚举原文；不能编造新值，不能因为选项排第一就选择。
- 置信度低于 0.7 的返回不落库；返回值还必须再次通过模板可见枚举文案校验，DeepDraw 选项 ID/code 不视为合法最终值。
- AI 等待期间字段被人工或其他任务修改时，使用快照条件更新跳过冲突字段，不覆盖新值。
- AI 服务不可用时返回警告，保留草稿和确定性规则结果，不把失败伪装成完成。

### 6.4 明确禁止 AI 生成的字段

- 销售尺码、主尺码表、唯品会/天猫/抖音/淘宝/多平台尺码表。
- 商家 SKU、条形码、单品货号和真实颜色/尺码组合。
- 充绒量(文本)的尺码克数。
- 原产国、执行标准、安全等级、材质百分比等缺少原始证据的合规事实；鞋垫材质的例外只允许在无明确鞋垫证据时选择模板中的`其他/其它`，不能选择具体材质。
- 例外仅是名称含“鞋子尺码表”的鞋品枚举字段：`22Q4-童鞋尺码表`、`25鞋子尺码表`、`25鞋子模板类型`；它们是单值枚举，不是结构表。

## 七、校验、发送与成功判定

- 必填性以当前深绘模板和有效父子条件为准；本地规则不能把模板不存在的历史字段变成阻断项。
- 枚举字段必须命中当前模板；多选值逐项校验。
- 销售尺码、SKU 尺码和所有结构表行键必须一致；结构表表头数量必须与每行单元格数量一致。
- 服饰没有真实 PLM 数据时，不生成零值尺码表，并保留缺少真实尺码表阻断。
- 鞋品创建成功后缺少数值 `productId` 时，完整平台尺码更新必须失败并记录原因。
- 深绘 HTTP 200 或业务码 `10200` 不能单独代表成功；还需检查业务响应和资源回读。
- 鞋品稳定发布回读成功至少核对：销售尺码、SKU 颜色/尺码组合、主表、唯品会、天猫、抖音逐行逐单元格一致；若本次 payload 发送了多平台尺码，也必须在同一次业务码 `10200` 后资源回读逐行一致，不能用本地构造或 HTTP 200 代替。
- 本文件描述代码发送能力，不代表已获授权重新提交历史线上商品；生产重提、push 和发布需单独授权。
